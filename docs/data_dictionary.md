# Data dictionary: `data/sales.db`

All data is **synthetic**, generated by `src/synthetic_data.py` (seed 7) for a fictional company,
Meridian Drinks Co. No real company data is used. The shape (30 SKUs, 3 regions, 36 months,
summer peaks, double-digit growth) mirrors a real FMCG distributor dataset so that the methods
transfer, but every value is invented.

| Table | Grain | Columns |
|---|---|---|
| `regions` | one row per region (3) | `region_id`, `region_name` |
| `products` | one row per SKU (30) | `product_id`, `product_name`, `category` (Carbonated, Water, Juice, Energy), `list_price_gbp` (per case), `launch_month`, `delist_after` (NULL if still listed) |
| `promotions` | one row per planned promotion | `month`, `region_id`, `product_id`, `discount_pct`, `planned_uplift` |
| `sales` | one row per month x region x SKU on sale | `month` (`YYYY-MM`), `region_id`, `product_id`, `volume_cases`, `revenue_gbp`, `on_promotion` (0/1) |

## Planted structure (known answers for testing)

| What | Where |
|---|---|
| Summer seasonality | strongest for Water and Carbonated, weak for Energy |
| Growth | 6-20% a year per SKU |
| Planned promotions | 12 SKUs; uplift 25-60%, discount 10-20%, small dip the month after |
| Launches | 3 SKUs from 2024-01, ramping up over 6 months |
| Delisting | 1 SKU, last month 2025-06 |
| Supply disruption | Carbonated, South, 2024-07: volume x 0.65 |

Because these patterns are planted, later results show whether a method **detects** them,
not that they exist in real markets.
